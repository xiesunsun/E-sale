# E-sale 学习手册

这个目录不是知识百科，而是 E-sale 的固定课程主线。代码始终只处在一个明确里程碑中；后续概念只记录，不提前实现。

## 当前坐标

- 层级：Layer 1 — Single-machine Software
- 版本：v0.1
- 里程碑：Milestone 0 — Understand One Request
- 当前问题：一次创建订单请求究竟发生了什么？
- 当前代码边界：FastAPI + SQLite，创建和读取订单
- 完成标准：能闭卷解释请求从 `curl` 到数据库文件的完整链路

## 固定学习循环

每个里程碑都按同一个循环推进：

1. **先预测**：运行前先写下自己认为会发生什么。
2. **最小实现**：只写足以暴露当前问题的代码。
3. **实际观察**：运行命令，保存关键输出和现象。
4. **解释断点**：找出自己的模型不能解释的那一步。
5. **引入抽象**：一次最多引入一到两个核心概念。
6. **修改系统**：让新理解在 E-sale 代码中落地。
7. **闭卷重建**：关闭资料，重新画图、讲解、写最小代码。
8. **验收**：让 AI 只当面试官或 debugger，不代替作答。

## AI 使用约定

- AI 不决定下一章；路线图决定。
- 旁支问题写入 `questions-parking-lot.md`，不立即展开。
- 提问前先给出自己的预测或运行模型。
- AI 每次最多补充两个新核心概念，并必须回到当前系统解释。
- 没有本机实验、没有闭卷复述的知识点，不算完成。
- AI 可以帮助定位断点，但不应一次重写全部答案或直接生成下一阶段架构。
